# Accessible Text Analyst

Многоязычный NLP-конвейер, спроектированный с упором на **доступность для программ экранного доступа** (NVDA, JAWS, VoiceOver, Narrator). Весь код, консольный вывод и отчёты построены так, чтобы ассистивные технологии разбирали их чисто: без ANSI-цветов, без эмодзи, без полос загрузки и без псевдографики.

> **Другие языки:** [English](README.md) · [polski](README_pl.md) · [suomi](README_fi.md) · [íslenska](README_is.md) · [italiano](README_it.md)

> **Статус i18n (v1.0).** Переведено только README. Повествование в блокноте, весь консольный вывод, `CLAUDE.md` и комментарии в коде остаются на исходных языках (в основном русский, в патчах и шаманском слое — польский). Перевод всего остального сознательно отложен на v1.1 — подробности в `release_notes.md`.

## Состав проекта

- `accessible_text_analyst.ipynb` — Jupyter-блокнот с полным аналитическим конвейером (40 ячеек: 20 кода + 20 markdown; повествование внутри блокнота — на русском). Записывает два артефакта доступности (`accessible_text.html`, `accessible_text.docx`), в которых каждый абзац и каждое иноязычное предложение несёт собственный атрибут `lang` — программы экранного доступа и движки TTS переключают голос автоматически, даже офлайн.
- `generate_report.py` — постпроцессор, превращающий выполненный блокнот в один доступный HTML-файл (`analysis_report.html`). Иноязычные фрагменты оборачивает в `<span lang="target_lang">`, а — независимо от языка корпуса — жёстко помечает `<span lang="en">` всё технически английское (POS-теги, NER-метки, идентификаторы моделей spaCy/Hugging Face, ASCII-пути). Inline-код и блоки кода в повествовании оптом получают `lang="en"`.
- `generate_md.py` — конвертирует `analysis_report.html` в `notebooklm_report.md` для NotebookLM. Spans доступности распаковываются, так как NotebookLM их не использует.
- `shamanic_pipeline.py` *(опциональный)* — постпроцессор без LLM, превращающий CSV/JSON-экспорт блокнота в четыре ритуальных текстовых артефакта (`oracle_script.txt`, `lore_fragments/`, `raw_roots_chant.txt`, `prophecies.txt`), полностью локализованных на все шесть поддерживаемых языков.
- `shamanic_ai.py` *(опциональный, с LLM)* — обращается к OpenAI, чтобы сгенерировать четыре повествовательных голоса (`Katla`, `Vieno`, `Lumi`, `Sami`) поверх тех же экспортов. Требует `OPENAI_API_KEY` в файле `golden_key.env`.
- `shamanic_locale.py` — пакет локализации для обоих шаманских скриптов (шаблоны, заголовки и резервные строки Lumi на всех шести языках).

## Что делает конвейер

1. Загружает текст из файла (`.pdf`, `.txt`, `.docx`, `.html` или изображений: `.png`, `.jpg`, `.jpeg`, `.tif`, `.tiff`, `.bmp`, `.webp`) либо из URL — удаляя повторяющиеся колонтитулы, боковые панели, разделы «Похожие статьи» и подобный шаблонный текст. Сканированные PDF и изображения обрабатываются через OCR (`pypdfium2` + `easyocr`).
2. Определяет язык корпуса через [`lingua-language-detector`](https://github.com/pemistahl/lingua-py). Доминирующий язык управляет конвейером spaCy; тот же детектор переиспользуется поабзацно и попредложенчно для языкомаркированного экспорта.
3. Загружает модели spaCy **в два этапа**. Сначала модель доминирующего языка обрабатывает весь корпус от начала до конца (токенизация → стоп-слова → лемматизация → POS → NER). Затем `cell_multilang_pass` повторяет языкоспецифичные NLP-проходы только для тех абзацев, чей детектированный язык отличается от доминирующего — подгружая каждую недоминирующую модель по требованию через `get_nlp()`, обёрнутый в `functools.lru_cache(maxsize=2)`. LRU-кэш имеет значение только на этом втором этапе; в любой момент в RAM не более двух моделей.
4. Токенизация → фильтрация стоп-слов → лемматизация → POS-тегирование → NER (двухступенчатый многоязычный NER с диспетчером моделей попредложенчно).
5. Векторные представления: Bag of Words, TF-IDF + автозапрос с косинусным ранжированием.
6. Структура: предложения → абзацы (по 3–6 предложений) → тезисы (лучшее предложение на абзац). Каждый абзац и каждое предложение помечается определённым кодом ISO 639-1.
7. Тематическое моделирование KMeans поверх абзацных векторов spaCy.
8. Экспорт CSV/JSON + текстовый сводный отчёт + доступный HTML и DOCX + глобальный HTML-отчёт (`analysis_report.html`).

## Языковая детекция

Детекция работает на трёх уровнях:

1. **Доминирующий в корпусе** — `cell_langdet` голосует по документам и выбирает доминирующий язык как `LANG`. Управляет конвейером spaCy.
2. **Поабзацно** (`para_langs`) — используется как атрибут `<p lang="...">` в `accessible_text.html` и как `<w:lang>` по умолчанию для каждого абзаца в `accessible_text.docx`.
3. **Попредложенчно** (`sent_langs`) — используется для оборачивания отдельных предложений в `<span lang="...">` внутри многоязычных абзацев (HTML) или для установки `<w:lang>` на попредложенческих runах (DOCX).

Поабзацная и попредложенческая детекция использует намеренно **консервативную обёртку `_safe_detect()`** в `cell_para`. Доверие сырому выводу lingua даёт слышимые артефакты: lingua неверно классифицирует короткие латинские фрагменты, в которых доминируют имена собственные («Igor de Lendorf» → it, «Mut se mies, Igor» → en), а программа экранного доступа, переключающаяся на английский голос на «Igor de Lendorf» и обратно на финский на следующем предложении, звучит хуже, чем если бы она прочитала имя собственное с финским акцентом.

Обёртка применяет следующие правила по порядку:

1. **Кириллица где-либо во фрагменте → `ru`.** Однозначно; работает даже на 3-символьных фрагментах.
2. **Фрагмент короче 30 символов → откат к `LANG`.** Lingua ненадёжна на коротких латинских фрагментах.
3. **Фрагмент содержит диакритики `LANG`** (например, `ä`/`ö` для `fi`, `ąęć` для `pl`) → откат к `LANG`. Финское предложение с английской цитатой остаётся финским.
4. **Lingua согласна с `LANG`** → принимаем.
5. **Lingua не согласна, но детектированный язык имеет СОБСТВЕННЫЕ характерные диакритики во фрагменте** (`à` для it, `ż` для pl, `ð` для is) → доверяем lingua.
6. **Lingua не согласна, и у детектированного языка нет характерных диакритик во фрагменте** (обычно `en`) → откат к `LANG`.

Мотивация правила 6 чисто фонетическая: английский голос, читающий финские/польские/итальянские фрагменты, даёт заметное искажение («бельтание фонем»), тогда как финский/польский/итальянский голос, читающий английскую цитату с лёгким акцентом, понятен и не раздражает. Компромисс: чисто английские предложения, встроенные в неанглийский корпус, читаются доминирующим голосом, а не переключаются на английский. Мы принимаем этот компромисс, потому что на практике пользователи программ экранного доступа сообщают об асимметричной потере качества.

Выпавшие из эвристики выбросы перечисляются в выводе `cell_para` для ручного просмотра (`Оставшиеся outlier-предложения...`). Та же логика диакритик управляет эвристикой пер-`<code>` (`_classify_code_lang`) в `generate_report.py` и пер-сегментным резервом lingua (`_lingua_word_fallback`) для путеподобных ASCII-идентификаторов.

## Требования

- Python 3.10 или новее.
- ~1,5 ГБ свободного места на диске под модели `_lg` spaCy (по одной на язык). Добавьте ~700 МБ, если включаете поддержку исландского (Hugging Face `transformers` + `torch` + IceBERT + MIM-GOLD-22).
- Добавьте ~700 МБ, если включаете поддержку OCR (`easyocr` подтягивает `torch` плюс собственные модели детекции и распознавания при первом вызове OCR). Если включена и поддержка исландского, стоимость `torch` делится между обеими опциями.
- Интернет-соединение при первом запуске (скачивание моделей).

## Конфигурация

Скопируйте образец конфигурации в локальный файл. Принимаются и `config.json`, и `config.ini` — **содержимое в любом случае JSON**; расширение `.ini` — чисто эргономическая уступка нетехническим пользователям Windows, у которых для `.json` нет ассоциированной программы.

```bash
# Выберите одно:
cp config.example.json config.json
cp config.example.ini  config.ini
```

`config.json` и `config.ini` оба в `.gitignore`, так что у каждого пользователя своя локальная копия.

Содержимое:

```json
{
  "source_file": "C:/path/to/document.pdf",
  "custom_patterns": [],
  "remove_noise": true,
  "ocr_languages": ["en"],
  "ui_lang": "",
  "lumi_katla_lines": null,
  "lumi_vieno_lines": null
}
```

| Ключ               | Тип             | Назначение |
|--------------------|-----------------|------------|
| `source_file`      | string          | Путь к файлу (`.pdf`, `.txt`, `.docx`, `.html` или изображению) **или** URL (`http://`, `https://`). Пустая строка или отсутствующий файл → встроенный пример корпуса. |
| `custom_patterns`  | string[]        | Необязательный список регулярных выражений, удаляемых из сырого текста (живые колонтитулы, повторяющиеся шаблоны). Пример: `["Editorial: .*", "Copyright \\d{4}"]`. |
| `remove_noise`     | boolean         | Переключает `generate_report.py` между читательским режимом (`true`, скрывает полосы загрузки Hugging Face/torch и таблицы лемматизации/POS) и полным диагностическим режимом (`false`). |
| `ocr_languages`    | string[]        | Языки для `easyocr` (используются только при сканированных PDF или изображениях). В одном экземпляре `easyocr.Reader` можно смешивать только языки одной письменности — например `["ru", "en"]` для кириллицы или `["en", "pl", "it", "fi", "is"]` для латиницы. |
| `ui_lang`          | string          | Язык UI для вывода в консоли и атрибута `<html lang>` сгенерированного отчёта (`pl` / `en` / `ru` / `fi` / `is` / `it`). Пустая строка или неизвестный код → fallback `en`. Независим от языка анализируемого корпуса — тот определяется автоматически. |
| `lumi_katla_lines` | integer или null | Необязательный лимит орнамента для итогового отчёта Лумми из `shamanic_ai.py`: сколько непустых строк монолога Катлы видит Лумми. `null` или отсутствие ключа = вся содержимое; integer N > 0 = первые N строк. |
| `lumi_vieno_lines` | integer или null | То же, что и `lumi_katla_lines`, но для песни отзвуков Виено. |

> **`ui_lang` — область локализации.** Консольный вывод четырёх скриптов вокруг конвейера (`generate_report.py`, `generate_md.py`, `shamanic_pipeline.py`, `shamanic_ai.py`) полностью локализован. Сам блокнот локализован *частично* — 16 заголовков секций (`--- Название ---`), весь итоговый отчёт `cell_summary` и приветствие «Q&A готова» в `cell_qa_rag` следуют за `ui_lang`, но диагностические принты на каждом шаге (детали загрузки корпуса, прогресс OCR, превью токенов/POS/NER, диагностика multilang-pass) остаются на русском. Блокнот — это инструмент для разработчика; **полностью локализованный пользовательский артефакт — `analysis_report.html`**, генерируемый `generate_report.py`. Переводы на `fi` / `is` / `it` сделаны в виде драфта и не выверены — сообщайте о шероховатостях на GitHub.

> **Пути Windows и регулярные выражения — важно.** Содержимое конфигурации — это JSON, а в JSON нет синтаксиса raw-строк. Одиночный обратный слэш экранирует следующий символ (`\U`, `\d`, `\n` — специальные), поэтому путь Windows, записанный как `"C:\Users\marek\doc.pdf"`, даст ошибку парсинга JSON. Два правильных способа:
>
> - **Прямые слэши** (проще всего, работают и на Windows): `"C:/Users/marek/doc.pdf"`.
> - **Двойные обратные слэши**: `"C:\\Users\\marek\\doc.pdf"`.
>
> То же правило действует для каждого регулярного выражения в `custom_patterns`: пишите `"\\d{4}"`, а не `"\d{4}"`; пишите `"Copyright \\d{4}"`, а не `"Copyright \d{4}"`. В JSON нет синтаксиса `r"…"` для raw-строк.

## Запуск

Скрипты ниже запускаются **по порядку**: каждый потребляет артефакты, созданные предыдущим.

### 1. Блокнот (обязательно)

```bash
jupyter notebook accessible_text_analyst.ipynb
# (Cell → Run All)
```

Это последовательный конвейер с общим глобальным состоянием. **Не меняйте порядок ячеек и не выполняйте их вне порядка.** Блокнот пишет `export_results/<project>/sentences.csv`, `paragraphs.csv`, `theses.csv`, `keywords_tfidf.csv`, `paragraphs_with_topics.csv`, `topic_keywords.json`, `entities.csv`, `accessible_text.html`, `accessible_text.docx` и `theses.txt`.

### 2. HTML-отчёт (рекомендуется)

```bash
python generate_report.py
# → export_results/<project>/analysis_report.html
```

`generate_report.py` читает вывод ячеек прямо из файла `.ipynb`, поэтому HTML-отчёт должен генерироваться из **свежевыполненного** блокнота. В `requirements.txt` указан `nbstripout` — если он активирован в локальной git-конфигурации, выводы блокнота стираются при коммите. Генерируйте отчёт _до_ коммита либо отключите nbstripout для своего workflow.

### 3. Markdown для NotebookLM (опционально)

```bash
python generate_md.py
# → export_results/<project>/notebooklm_report.md
```

Конвертирует HTML-отчёт в Markdown с распакованными spans доступности (NotebookLM не использует `<span lang="…">`). Запускайте только если хотите загрузить отчёт в NotebookLM.

### 4. Шаманский постпроцессор без LLM (опционально)

```bash
python shamanic_pipeline.py
# → export_results/<project>/audio_scripts/oracle_script.txt
#                                          /raw_roots_chant.txt
#                                          /prophecies.txt
#                                          /lore_fragments/intercepted_log_T*_P*.txt
```

Генерирует четыре ритуальных текстовых артефакта прямо из CSV/JSON-экспорта блокнота — без вызова LLM, без сети. Все строки берутся из `shamanic_locale.py` и полностью локализованы на все шесть поддерживаемых языков.

### 5. Шаманский LLM-постпроцессор (опционально, требует ключ OpenAI)

```bash
python shamanic_ai.py
# → export_results/<project>/audio_scripts/katla_entity_monologue.txt
#                                          /vieno_echoes_chant.txt
#                                          /lumi_final_report.txt
#                                          /sami_energetic_spark.txt
```

Требует API-ключ OpenAI. Создайте `golden_key.env` в корне проекта:

```
OPENAI_API_KEY=sk-...
```

`golden_key.env` подпадает под `*.env` в `.gitignore`, так что не закоммитится. Четыре голоса исполняются по очереди:

1. **Katla** превращает список сущностей (`entities.csv`) в монолог замёрзших северных духов.
2. **Vieno** напевает над списком ключевых слов/тем, вплетая пять сырых предложений из корпуса как отголоски из другого измерения.
3. **Lumi** читает `prophecies.txt` (обязательно) плюс монолог Katla и песню Vieno (опциональное украшение) и выдаёт финальный рапорт. Локализованные строки-резервы обрабатывают случай, когда Katla или Vieno отсутствуют.
4. **Sami** читает рапорт Lumi и выдаёт высокоэнергичный синтез с искрой надежды или призывом к действию.

## Вывод

Каждый проанализированный корпус получает свой подкаталог в `export_results/`, названный по исходному файлу (без пути и расширения) или по `domain_slug` для URL. Встроенный пример корпуса использует `export_results/_default/`.

Каждый подкаталог содержит:

## Доступность

Это центральная ценность проекта. Всё ниже сознательно и должно сохраняться при модификациях конвейера:

- **Никаких ANSI-цветов, эмодзи и псевдографики в stdout.** Программа экранного доступа читает каждый символ буквально — `[OK]` вместо «🟢», `---` вместо «───━━━».
- **Подавленные полосы загрузки** (`tqdm`, `transformers`, `torch`) — `cell_model._silence_hf_progress()` глушит полосы загрузки и предупреждения Hugging Face/torch перед загрузкой IceBERT и MIM-GOLD-22 для исландского; `cell_corpus._silence_ocr_progress()` делает то же для `easyocr`.
- **Атрибуты `lang` поабзацно и попредложенчно в экспорте.** `accessible_text.html` и `accessible_text.docx` несут код ISO 639-1 на каждом абзаце (и на каждом предложении внутри многоязычных абзацев / runов). NVDA, JAWS, Narrator, VoiceOver, Word и SAPI учитывают эти теги и переключают голос автоматически — даже офлайн.
- **Жёстко зашитое обозначение английского в HTML-отчёте.** `generate_report.py` всегда оборачивает технически английские фрагменты — POS-теги (`NOUN`, `VERB`, `ADJ`), NER-метки (`PER`, `ORG`, `[orgName]`), идентификаторы моделей spaCy / Hugging Face, ASCII-пути, блоки кода — в `<span lang="en">`, чтобы они больше не произносились голосом документа по умолчанию (русским).
- **Пер-фрагментная разметка иноязычного корпуса в HTML.** Когда корпус не русский, структурированные выводы (цитаты предложений, списки ключевых слов, слова тем, строки ранжирования RAG, таблицы лемматизации) оборачиваются в `<span lang="target_lang">`.
- **Линейная структура HTML** (`<main>`, корректная иерархия заголовков).
